# Shared website UI in immersive VR

The headset shows the room website's own overlay. `RoomXRPanel` renders the same markup and `room-x` classes as `RoomExperience`: the top bar, the selected piece's toolbar and details, search results, the placement card, the Talk and Add furniture pills, the nine-slot hotbar, and the Add furniture, Basket and Inventory drawers with the shared `RoomProductCard`. Icons come from `room-icons.tsx`, which both surfaces import. The DOM is laid out at 640 × 444 CSS px, rasterized at 2.25× onto a transparent 1440 × 1000 texture, and floats over the room the way the website's overlay floats over its canvas. `RoomXRPanel.css` changes only placement, motion and hover, plus slightly denser glass: html2canvas cannot see `:hover` or backdrop blur, so controller hover is mirrored through `[data-xr-hover]`.

Only painted UI (`[data-xr-solid]` and buttons) owns a controller ray. Rays through the transparent gaps select furniture and floor, as clicking the website's canvas does. There is no text entry in VR, so the catalog uses the category chips; checkout stays on the website.

`RoomExperience` supplies the existing canonical shopping session, voice state, current recommendation, room inventory and basket. The open room is the Agent view (voice pill, captions, results); drawers hold the catalog, basket, inventory and controls. The VR adapter measures actual `[data-xr-id]` DOM buttons and routes controller selection to their React click handlers. Accepted mutations still run through the existing room operations. Preview and approval remain separate; payment remains in the normal website.

The right thumbstick scrolls while its ray intersects the panel; horizontal snap turning is suppressed during panel interaction. Left-stick movement, head-relative following, grip controls and the existing laser alignment remain in the WebXR engine. The catalog is bounded to 24 products and retains an active preview from a later result or Fetch. Lists are scrollable, with a persistent approval footer.

Rasterization is lazy-loaded and coalesced to at most ten captures per second, outside the headset animation loop. The renderer uses one persistent 1440 × 1000 canvas texture and one 1.04 m plane. State/layout generations protect against clicking controls from an obsolete snapshot. Offscreen DOM never opens a microphone or moves focus. Disposal removes the React root, listeners, font-metric workaround, host and GPU resources.

Merchant photos need CORS permission before they can be uploaded as a WebGL texture. IKEA's ordinary photo response does not supply that permission. `/api/product-image` fetches only HTTPS product-image paths on the exact IKEA and Target image hosts, omits credentials, forbids redirects, enforces supported image types, times out, and limits both declared and streamed size to 5 MiB. The ordinary website retains its direct image URLs. Unknown or failed photos show an honest placeholder.

Tailwind's image display reset also affects html2canvas's hidden one-pixel font-measurement image. A narrowly scoped stylesheet corrects only that measurement element, preserving merchant image styling. Keep this workaround with the rasterizer rather than changing global website typography.

`/dev/vr-ui` renders the same texture and click path with saved real catalog products and explicitly synthetic room/fit, inventory and basket data. Its voice controls simulate UI state only. Browser visual checks, actual React DOM regression tests and physical Quest verification are complementary; the simulator does not establish headset performance.
